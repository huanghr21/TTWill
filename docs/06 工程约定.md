## 统一 LLM 调用层

所有模型调用（协调者、子 Agent、确认判定、基线组；以及我们自己发起的模拟用户与判分调用）都经过一层薄封装。

| 职责 | 说明 |
| --- | --- |
| 统一接口 | 对上提供一个调用函数（消息、工具、模型档位），对下适配具体服务（DeepSeek 等） |
| 模型档位 | 代码中只写档位（如 `flash` / `strong`），档位到具体模型的映射放在配置里 |
| 计量 | 每次调用记录输入 / 输出 / 缓存命中 token、费用、延迟，写入轨迹 |
| 重试与超时 | 统一处理，重试次数计入轨迹 |
| 测试替身 | 提供假模型实现，测试不调用真实服务 |

EchoMind 与 OrderWeave 都已能使用 DeepSeek，接入本身不是难点；这一层的价值在于**成本统计、模型分层和测试替身集中在一处**。

## 轨迹

### 用途

| 用途 | 说明 |
| --- | --- |
| 调试与失败分析 | 区分是协调者拆错任务、子 Agent 执行错，还是护栏误拦 |
| 实验指标 | 误写操作、遗漏子任务、成本等指标从轨迹统计 |
| 演示 | 实时网页的链路面板直接消费轨迹事件 |
| 回放 | 用记录的模型输出离线重放，不再调用模型 |

### 数据模型：span 树

参照 OpenTelemetry 的思路，但不引入其依赖。一次会话是一棵树，每个节点是一个 **span**（一段有开始和结束的操作）：

```text
session                         一段完整对话
└─ turn                         用户的一轮消息
   ├─ coordinator               协调者处理这一轮
   │  ├─ llm                    协调者的模型调用
   │  ├─ task_update            任务清单变化（前 → 后）
   │  ├─ dispatch               派出子 Agent（任务说明）
   │  │  └─ subagent            子 Agent 执行
   │  │     ├─ llm
   │  │     ├─ tool             工具调用（参数、结果）
   │  │     │  └─ guard         护栏检查（放行 / 拦截 + 原因）
   │  │     └─ result           结构化返回
   │  ├─ confirmation           确认判定（用户原话、判定结果）
   │  └─ reply                  最终回复
   └─ state_snapshot            本轮结束时的任务状态
```

### span 公共字段

| 字段 | 说明 |
| --- | --- |
| `span_id` / `parent_id` | 组成树 |
| `session_id` / `turn` | 所属会话与轮次 |
| `kind` | 上面树中的类型 |
| `name` | 具体名称（如能力名、工具名） |
| `start` / `end` | 时间戳 |
| `status` | `ok` / `error` / `blocked` |
| `attrs` | 按类型不同的内容（见下） |

各类型的 `attrs`（初稿）：

| kind | attrs |
| --- | --- |
| `llm` | 模型、档位、输入消息引用、输出、token、费用、延迟 |
| `tool` | 工具名、参数、结果、读 / 写、执行状态（prepared / executed） |
| `guard` | 护栏名、判定、原因 |
| `dispatch` | 能力名、任务 ID、任务说明 |
| `result` | 子 Agent 的结构化返回 |
| `task_update` | 变更前后的任务清单 |
| `confirmation` | 待确认操作、用户原话、判定结果与依据 |

### 实现要点

- **上下文自动传递父节点**：用 Python `contextvars` 记录当前 span，`with trace.span("tool", name): ...` 自动挂到正确的父节点下，业务代码不需要手动传 ID；
- **事件流 + 落盘**：span 开始和结束时各发一个事件。事件同时写入 JSONL 文件（每会话一个），并推送给订阅者（实时网页）；
- **大内容引用化**：完整的提示词和模型输出单独存储，span 里只放引用和摘要，避免轨迹文件膨胀；
- **入口唯一**：LLM 调用层、工具网关、护栏、协调者分派这几个入口自动打点，业务代码基本不用手写；
- **脱敏**：如果后续接入真实数据，在写入前脱敏（EchoMind 已有 `redaction.py` 可复用）；
- **查看器**：MVP 先提供命令行树状查看；实时网页在 MVP 之后做。

## 实验记录

| 项 | 约定 |
| --- | --- |
| 每次运行记录 | 代码版本（git commit）、模型与档位映射、提示词版本、τ² 版本、随机种子、实验组别、任务集 |
| 运行目录 | `runs/<run_id>/`：配置快照、每会话轨迹、结果汇总；同一 `run_id` 重跑只补缺失的会话 |
| 隔离 | 每个会话使用独立的业务数据与状态 |
| 结果 | 失败、无效、未运行都保留并计入分母，不挑最好的结果。基础设施错误（API 超时、限流、网络错误）不算 Agent 失败：在调用层重试，仍失败的会话标记为“未运行”并补跑，次数写入结果汇总 |
| 比较 | 按题配对，bootstrap 置信区间 |
| 费用 | 所有调用写入同一费用账本，可设预算上限 |
