## 统一 LLM 调用层

所有模型调用（Agent、确认判定、摘要，以及我们自己发起的模拟用户与判分）都经过一层薄封装：统一接口；代码里只写模型档位（如 `flash` / `strong`），映射放在配置里；每次调用记录 token、费用、延迟并写入轨迹；统一处理重试与超时；提供假模型供测试使用。

**例外：τ² 内部的调用。** τ² 自带的用户模拟器和判分组件在 τ² 内部通过 LiteLLM（一个统一调用各家模型的开源库，τ² 的依赖）发起请求，不经过我们的调用层。不修改 τ² 的代码，而是通过 LiteLLM 的回调（callback）把这些调用的 token 与费用记入同一个费用账本。

## 轨迹

### 用途

| 用途 | 说明 |
| --- | --- |
| 调试与失败分析 | 区分是协调者拆错任务、子 Agent 执行错，还是护栏误拦 |
| 实验指标 | 误写操作、遗漏子任务、成本等指标从轨迹统计 |
| 演示 | 实时网页的链路面板直接消费轨迹事件 |
| 回放 | 用记录的模型输出离线重放，不再调用模型 |

### 数据模型：span 树

参照 OpenTelemetry 的思路，但不引入其依赖。一次会话是一棵树，每个节点是一个 **span**（一段有开始和结束的操作）：

```text
session                         一段完整对话
└─ turn                         用户的一轮消息
   ├─ coordinator               协调者处理这一轮
   │  ├─ llm                    协调者的模型调用
   │  ├─ task_update            任务清单变化（前 → 后）
   │  ├─ dispatch               派出子 Agent（任务说明）
   │  │  └─ subagent            子 Agent 执行
   │  │     ├─ llm
   │  │     ├─ tool             工具调用（参数、结果）
   │  │     │  └─ guard         护栏检查（放行 / 拦截 + 原因）
   │  │     └─ result           结构化返回
   │  ├─ confirmation           确认判定（用户原话、判定结果）
   │  └─ reply                  最终回复
   └─ state_snapshot            本轮结束时的任务状态
```

### span 公共字段

| 字段 | 说明 |
| --- | --- |
| `span_id` / `parent_id` | 组成树 |
| `session_id` / `turn` | 所属会话与轮次 |
| `kind` | 上面树中的类型 |
| `name` | 具体名称（如能力名、工具名） |
| `start` / `end` | 时间戳 |
| `status` | `ok` / `error` / `blocked` |
| `attrs` | 按类型不同的内容（见下） |

各类型的 `attrs`（初稿）：

| kind | attrs |
| --- | --- |
| `llm` | 模型、档位、输入消息引用、输出、token、费用、延迟 |
| `tool` | 工具名、参数、结果、读 / 写、执行状态（prepared / executed） |
| `guard` | 护栏名、判定、原因 |
| `dispatch` | 能力名、任务 ID、任务说明 |
| `result` | 子 Agent 的结构化返回 |
| `task_update` | 变更前后的任务清单 |
| `confirmation` | 待确认操作、用户原话、判定结果与依据 |

### 实现要点

- 用 `contextvars` 记录当前 span，`with trace.span("tool", name): ...` 自动挂到父节点下；
- span 开始和结束各发一个事件，写入每会话一个 JSONL 文件，同时推送给订阅者（实时网页）；
- 完整提示词和模型输出单独存储，span 里只放引用；
- 在 LLM 调用层、工具网关、护栏、协调者分派这几个入口统一打点；
- MVP 先提供命令行树状查看。

## 实验记录

| 项 | 约定 |
| --- | --- |
| 每次运行记录 | 代码版本、模型与档位映射、提示词版本、τ² 版本、随机种子、实验组别、任务集 |
| 运行目录 | `runs/<run_id>/`：配置快照、每会话轨迹、结果汇总；同一 `run_id` 重跑只补缺失的会话 |
| 隔离 | 每个会话使用独立的业务数据与状态 |
| 结果 | 失败、无效、未运行都保留并计入分母。基础设施错误（超时、限流、网络）不算 Agent 失败：重试后仍失败的标记为“未运行”并补跑 |
| 比较 | 按题配对，bootstrap 置信区间 |
| 费用 | 所有调用写入同一费用账本，可设预算上限 |
