# 用户画像约定

> 最近更新：2026-11-12　｜　状态：基本约定已确定，具体规则在第二阶段细化
>
> 画像主要服务**导购**（第二阶段），MVP 不涉及。

## 已确定的约定

| # | 约定 |
| --- | --- |
| 1 | 画像使用**结构化记录**，不使用大模型自由生成的一段描述文本 |
| 2 | 来源包括用户明确表达和平台行为（浏览、收藏、购买、退货）；行为需结合上下文解读 |
| 3 | 由 Agent 在对话中补充和修正画像，每条记录保留来源依据 |
| 4 | 画像参与**商品召回与排序**，而不只是影响最后的推荐话术 |
| 5 | 召回效果不好时，能退回到关键词或具体商品实例查找 |
| 6 | **当前明确需求优先于历史画像**；本次购物条件默认不写入长期画像 |

## 为什么不沿用 EchoMind 的做法

EchoMind 现有做法（`memory/conversation_memory.py` 的 `_update_profile`）：用 LLM 从最近对话提炼 `{"preferences": [...], "entities": {...}}`，整块写入 ChromaDB。

| 问题 | 影响 |
| --- | --- |
| 偏好是自由文本 | 无法用于结构化过滤与排序 |
| 不记录来源 | 无法解释“为什么推荐这个”，也无法判断可信程度 |
| 不区分长期与本次 | “给父亲买”可能被误记为用户本人的偏好 |
| 没有置信度与时效 | 一次浏览和多次购买权重相同；旧偏好不会淡出 |
| 整块覆盖更新 | 新提炼结果可能丢失旧的有效信息 |

## 三类信息

| 类型 | 例子 | 存放与使用 |
| --- | --- | --- |
| 行为事实 | 浏览了 A，收藏了 B，购买了 C，退了 D | 平台保存原始记录，作为推断依据；本身不直接等于偏好 |
| 长期偏好 | 不喜欢入耳式耳机；常选轻便产品 | 画像记录，跨会话使用，允许修正 |
| 本次购物条件 | 给父亲买、预算 300 元、周末要用 | 只存在于当前任务状态中，直接约束本次推荐 |

## 画像记录结构（初稿）

每条偏好是一条独立记录：

```json
{
  "user_id": "u_001",
  "category": "耳机",
  "attribute": "佩戴方式",
  "value": "非入耳式",
  "polarity": "prefer",
  "source": "explicit",
  "evidence": "对话 c_123：‘入耳式戴着耳朵疼’",
  "confidence": 0.9,
  "scope": "long_term",
  "updated_at": "2026-11-12T10:00:00"
}
```

| 字段 | 说明 |
| --- | --- |
| `category` | 适用品类；跨品类偏好（如“偏好轻便”）可为 `*` |
| `attribute` / `value` | 对应商品库中的属性名与取值，便于直接用于过滤和排序 |
| `polarity` | `prefer` / `avoid`；也可扩展为数值权重 |
| `source` | `explicit`（明确表达）/ `purchase` / `favorite` / `browse` / `return` |
| `evidence` | 来源依据：对话片段或行为记录 ID，用于解释与审计 |
| `confidence` | 可信度，由来源与次数决定 |
| `scope` | `long_term` / `session`；本次条件默认 `session`，不进入长期画像 |
| `updated_at` | 用于时效衰减 |

此外可保留一份简短的**画像摘要**（文本），用于语义检索和提示词，但以结构化记录为准。

## 来源的解读（初步规则，待细化）

| 来源 | 初步处理 | 需要注意 |
| --- | --- | --- |
| 明确表达 | 高置信度，直接记录 | 区分“我一直……”（长期）与“这次……”（本次） |
| 购买 | 中等置信度 | 可能是送礼；结合收货人、对话说明判断 |
| 收藏 | 较低置信度 | 表示兴趣，不一定代表偏好 |
| 浏览 | 低置信度，多次才计入 | 可能只是在比较 |
| 退货 | 视退货原因而定 | 尺码不合 ≠ 不喜欢这个商品；质量问题可能指向品牌或型号 |

具体阈值、置信度计算与衰减方式，在第二阶段确定。

## 更新方式

- **Agent 通过工具写入**：如 `upsert_preference`，每次只增改相关条目，不整块覆盖；
- **冲突处理**：明确表达覆盖行为推断；新的明确表达覆盖旧的明确表达，并保留历史；
- **用户可查看与修正**：例如“我现在不介意入耳式了”，对应记录被更新；
- **本次条件不自动转长期**：只有用户明确表示是长期偏好，或多次重复出现时，才提升为 `long_term`。

## 在导购中的使用

| 环节 | 画像的作用 |
| --- | --- |
| 查询构造 | 用户需求模糊时，用高置信度偏好补充查询条件 |
| 召回 | 增加一路“画像召回”（与偏好匹配的商品），和需求召回合并 |
| 过滤 | 只有明确表达的 `avoid` 可作为硬过滤；推断出的偏好不作硬过滤 |
| 排序 | 偏好匹配度作为排序特征之一，权重低于当前需求 |
| 推荐解释 | 引用 `evidence` 说明依据，例如“你之前提到入耳式不舒服” |
| 降级 | 召回不足时，退回关键词检索或“与你买过的 X 类似”的实例查找 |

**与当前需求冲突时**：当前需求优先；如果送礼等场景明显与本人画像无关，本次不使用画像，必要时追问确认。
